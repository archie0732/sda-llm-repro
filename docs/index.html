用 Claude 重現 SDA-LLM，我學到的事

我用 Claude 小規模重現了 SDA-LLM（IROS 2025）的「用多輪對話找出指定物件」，並加了幾個論文沒有做的對照。這頁記錄我做了什麼、每個關鍵判斷為什麼這樣下，以及我的心得。

論文在做什麼

想像你對機器人說「幫我找那張椅子」，但房間裡有十幾張椅子。SDA-LLM 的做法是讓機器人原地每 45° 拍一張照片，共 8 張，在每個物件上貼一個編號（例如 chair 3），再把這 8 張圖交給視覺語言模型（論文用 GPT-4o）。使用者一句一句描述，模型每一輪回答「還剩哪些候選」，直到只剩一個。

整個系統分兩層。第一層用作者自己訓練過的 YOLOv8 找物件，再算位置、刪掉在不同照片重複出現的同一個物件，最後貼上編號。第二層負責用對話縮小範圍。我重現的是第二層，第一層的編號直接用作者標好的，所以差距只會來自對話這一層。

論文用兩種分數。T_A 用在「找出一個指定物件」的題目，T_B 用在「每輪回報符合的有幾個」的題目。作者自己拍的 Office 場景，GPT-4o 的 T_A 是 0.86。

我做了什麼

我把實驗分成兩條線。Track V 用作者在 GitHub 公開的資料，Track R 用 Apple 的 ARKitScenes 自己生成更多題目。模型是 claude-sonnet-5-5，全部付費呼叫約 2 美元。

實驗做法想回答的問題
V1 重現Office 15 題，用作者的提示詞原文與評分公式，換成 Claude換模型之後分數差多少
人類基準我自己照同樣規則一句一句作答這組題目人能拿幾分
純文字、拼圖、圖加座標拿掉圖、把圖拼成一張、圖加座標表圖到底有沒有幫上忙
C5 強迫選一個跟重現完全相同，只在最後一句後要求「只回一個最可能的編號」模型是看錯，還是不敢下決定
V2 數量題40 題每輪回報數量，我再逐題看模型最後指的是不是對的物件數量答對是不是等於找對

四個觀察

題目數量很少，下面這些我都當成想請教作者的問題，不是定論。

一、照公開的對話檔重播，拿不到 0.86

我自己看圖、照同樣規則作答，也只有 0.733。有幾題只有一句「玻璃牆旁邊那張椅子」，我看完圖還是剩兩張，沒有下一句可以再縮小。我讀作者公開的程式，發現對話是由人在現場即時輸入，直到使用者確認才結束。所以我猜論文的評估可能包含了人當場的追問，跟「照檔案一句一句播」是不同的設定。

二、Claude 常常不是看錯，而是不肯選一個

在論文的設定下，Claude 最後的答案裡有正解的比例是 0.889，但剛好只選一個而且選對的比例只有 0.444。我只在最後加一句「請只回一個最可能的編號」，其他完全不變，找到的比例就從 0.44 升到 0.84，跟我自己的 0.73 差不多。換句話說，它多半知道答案在哪兩三張裡，只是不敢收斂。

三、公開的標註檔和答案檔，白板用的是兩套編號

Office 有四題在問白板，我和 Claude 一開始都一致答成答案檔的下一號。我一度以為是作者標錯，但對照原始檔案後發現，答案檔說「愛心旁邊的白板」是 whiteboard 1，而公開的標註框把愛心旁邊那塊叫做 whiteboard2。

原始照片上其實沒有框，框是我的程式照標註檔畫上去的。我回頭讀作者的程式，發現當初給 GPT-4o 看的圖只框題目問的那一類，編號由偵測程式依順序自動產生，白板那組圖沒有公開。所以這比較可能是兩套編號系統，而不是誰標錯。

我的處理方式是保留作者要找的物件，只把編號翻譯成我圖上的名稱，而且只用在這四題，判斷依據是描述和圖片，不看模型的答案。主要結果用翻譯後的正解，原本編號的分數也一併列出。

四、數量答對不等於找對

數量題只檢查「有幾個」。最後一輪數量答對的 34 題裡，我人工確認只有 23 題真的指到對的物件。反過來，數量答錯的 6 題裡有 4 題其實指對了。只看數量會高估模型真的找到東西的比例。

過程中的判斷

這次實驗程式大部分由 Claude Code 照我寫的計畫書實作，我負責研究問題、實驗設計，以及每一個需要人判斷的地方。下面是我覺得最重要的幾個決定。

分數很低時，先懷疑自己

第一次全跑只有 0.10，我的第一個反應是程式寫錯了。所以我先自己當受試者作答，確認題目本身在這個設定下人能拿幾分，再從原始紀錄重算每個數字。這兩步讓我有信心說差距不是 bug。

對照實驗一次只改一件事

C5 跟原本的設定完全相同，只多了最後一句。我刻意不改最上面的系統提示，也不為任何條件個別調提示詞，這樣分數的差異才能歸因到「強迫選一個」。

只翻譯編號，不重新決定答案

白板題對不上時，最省事的做法是「我們覺得對的就是答案」。但這樣分數就變成我說了算，而且被評分的是 Claude，由我和 Claude 來當裁判也不公平。所以我定了規則，只把作者要找的物件換成我圖上的編號，其他題目就算我覺得有歧義也不改。我做人工檢查時也犯過錯，第一次把「寫字在哪一塊白板上」讀成「寫字那塊旁邊的白板」，後來才更正。這讓我知道人工檢查的題目本身要寫得很清楚。

寧可少框，也不要畫錯框

自己生成題目時，有些椅子塞在桌子底下，深度相機量到的其實是桌面，框就畫到桌布上去了。我加了兩條規則，離地 5 公分內的像素不算，同時落在兩個物件裡的像素也不算。代價是整張塞在桌下的椅子會沒有框，但我認為錯的框比少一個框更傷題目品質。

跨圖去重

8 張照片是繞一圈拍的，同一張椅子可能同時出現在兩張照片裡。如果不處理，它會拿到兩個編號，使用者說「那張椅子」時就永遠縮不到一個。論文只說「依距離刪除重複的物件」，沒有寫門檻與做法，所以我把這一步拆出來測。

做法是先算出每個框裡的物件在房間裡的 3D 位置，再把「同類別而且距離小於 τ 公尺」的框當成同一個物件。三種方法的差別在 3D 位置怎麼算。

方法怎麼算位置比喻
D1 不去重不合併，每張照片的每個框都當成不同物件每張照片各自點名，同一個人被點兩次
D2 框中央只看框正中間那一小塊的深度拿雷射筆往框中間打一下量距離，椅子塞在桌下時打到的是桌面
D2b 物件像素用真正屬於這個物件的所有像素取中間值在椅子身上打很多點再取中間，比較不會被桌面騙

我用 ARKitScenes 的標註當正解（標註知道哪些框其實是同一張椅子），8 個場景共有 91 對「應該合併」的框。

precision 是「我說是同一個的，有幾成真的是」，recall 是「真的是同一個的，我抓到幾成」。最好的是 D2b、τ = 0.5，說合併時 93% 是對的，但還有四成重複沒抓到。不去重的話，每個場景平均多算 8 個物件。

我的解讀很簡單。就算每個物件的輪廓都切得完美，只靠「距離夠近就合併」還是不夠。門檻設小，大沙發從兩個方向看會被當成兩個。門檻設大，並排的兩張椅子又會被併成一張。我猜還需要看外觀，例如顏色與形狀，這是我之後想試的方向。

限制

  • Office 只有 15 題，差一題就是 0.067，小差距我都不下結論。
  • 人類基準只有我一個人做一次，數量題的人工判斷也只有我，有 7 題我看不出來。
  • 目前的模型不能固定隨機性，所以每個條件跑 3 次報範圍，數量題只跑 1 次。
  • 我用 Claude，不是論文的 GPT-4o。
  • 我給模型的圖把所有類別的框都畫上，作者只框題目問的那一類，我的圖比較雜亂。
  • 作者 view 3 的標註檔是 view 2 的複本，所以我的 view 3 上有一個沒有框到白板的「whiteboard 2」，這一版沒有重跑。
  • 自己生成的題目目前只有 8 個場景 42 組對話，主實驗還沒跑。
  • 作者的資料沒有授權檔，ARKitScenes 只能非商業研究使用，所以這頁沒有放任何資料集的圖片。

心得

我原本以為重現就是把程式跑一遍、對一下分數。實際做了才發現，分數對不上時，真正的工作才開始。我要一個一個排除可能的原因，先懷疑自己的程式，再懷疑評估方式，最後才懷疑資料。

我印象最深的是 C5。只加一句話，分數就從 0.18 跳到 0.58。這讓我意識到，評估一個模型時，「它會不會」和「它肯不肯回答」是兩件事，而現在的指標常常把這兩件事混在一起。

白板題讓我學到，結果對不上時不能急著下結論。我一開始以為是作者標錯，直到發現原始照片上沒有框，才意識到是我給模型的輸入跟作者的不一樣。如果我沒有回頭查，就會把自己的重現差異說成別人的錯誤。

我也學到人工檢查不是理所當然正確的。我自己就在白板題上讀錯了一次題目。之後我做任何需要人判斷的檢查，都會先把問題寫清楚，並把我的判斷存下來讓別人可以複查。

最後，這次我大量使用 Claude Code 寫程式。我發現 AI 讓實作變快，但決定要測什麼、怎麼解讀結果、哪些數字不能信，還是要靠自己。我覺得這正是做研究最有意思的部分。

這是我個人獨立的學生重現練習，與原論文作者及 Apple 沒有隸屬關係。所有數字的來源與每一步紀錄都在 repo 的 results/RESULTS.md 與 results/LOG.md。如果我的理解有錯，非常歡迎指正。
